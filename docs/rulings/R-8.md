## Context
A private CLI's agent docs live only in its own repository, so an agent in a repository that CLI generated cannot read them. The owner asked for a shared mechanism taken from a2a, which already embeds its docs, installs them, links them to each agent runtime, writes a pointer and reports drift.

## Decision
Build `units/agentdocs` as one module at the go 1.25 floor, ported test-first from a2ahub with a parity check. Its API is docs/features/active/agentdocs-2026-11/specs/01-api.md:
- the manifest and topics, plus `TopicFor(path)`, matching the longest command-path prefix;
- install with a provenance marker, and an installed-copy status with Severity;
- the agent-surface rows and the link;
- the context-file pointer;
- a staleness check for generated files.

Content, CLI wiring, doctor wording and the reference generator stay with each tool. A cobra tool uses cobra/doc.

## Consequences
Provider facts are verified in one place for every tool. Install-on-init versus an explicit verb is a caller choice, so a consumer's own call on it does not change the API. a2a switches later in its own lane, renaming its manifest schema. The port costs about 2–3 hours, then v0.1.0 through unit-release.sh (R-2, R-7).
