## Context
A Go unit can have a counterpart in another stack (Go auth with Nuxt auth): working mechanisms, no styles.

## Decision
`unit.json` `pairs` is the pointer: `{stack, repo, unit, contract}`. A foundation repo for another stack (for example `nuxt-foundation`) uses the same capability ids and the same unit.json shape. The contract between the halves (HTTP/API schema) lives in the server unit's `contract/`, versioned by that unit's tag; the client half names the tag it was built against.

## Consequences
The cross-repo check that a pair resolves needs the second repo; it is a backlog row until then.
