## Context
A shared library turns into entropy when nobody knows who uses what at which version, and when consumers copy instead of import.

## Decision
The registry is derived, never hand-kept. The one hand-kept list says only where to look; it names private repositories, so it lives in the host registry (~/Developer/_ops/registry/foundation-consumers.txt, foundation-kit D-6), never in this public repository (R-6). `make consumers` reads each repo's go.mod through gh and code-searches the stamp `go-foundation-copy: <unit>@<sha>`, and writes the table beside the list (foundation-consumers.md, committed by the host registry's owner): per unit and repo, current / behind / copy, and unused units. UNITS.md is generated from unit.json. How to adopt: every unit README has the headings Install / Wire / Configure / Extension points / Do not, and every release ships adoption notes with detects. No forks: extend through options and interfaces; a change one consumer needs is made upstream; a copy needs the stamp and a backlog row to remove it.

## Consequences
`make consumers` needs the network, so it runs at every unit release, never in make check. A copy stays visible until it is replaced by an import.
