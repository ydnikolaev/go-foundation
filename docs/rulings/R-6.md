## Context
a2ahub and sporo are public; a public repo cannot import a private module, and a private unit shared by a public and a private consumer brings the access problem back (GOPRIVATE, git credentials, vendoring). Asked 2026-11-08 with three options: public, private, or a public/private split.

## Decision
go-foundation is ONE public repository, Apache-2.0 (as a2ahub), with no private sibling. Recorded in devkit as foundation-kit D-6; the owner's words below were relayed by devkit-cto. Before the flip the history is rewritten (git filter-repo) so no commit ever named a private repo, and the unit tag is re-cut on the rewritten history; the owner chose the rewrite directly ("давай так", 2026-11-08) and runs the force-push. In the same push the unit moved under `units/` (R-1), so `adoption/v0.1.0` is deleted and `units/adoption/v0.1.0` cut over the same unit code with the new module path: nothing had cached the old tag while the repository was private.

What a public repo may not publish is a gate, not a habit: `make public-scan` refuses, over the tree and every ref's history, a private repo name (derived through `gh repo list --visibility private` at run time, so no list of private names is ever committed), an absolute host path, an email other than a noreply or `git@<host>`, and a gitleaks secret. Its one exception file is config/public-allowlist.txt; an exempt path needs a written reason. It needs gh, so it runs before every push and visibility change, never in public CI; its teeth run offline in make check.

Commit author and committer fields are not judged: the owner's address is already published in every public a2ahub commit (2,563 measured on 2026-11-08), and judging it would refuse every commit.

## Consequences
Consumers need no GOPRIVATE, token or vendoring. The consumer list, which names private repos, lives in the host registry (R-5). A managed devkit file that names a consumer or a host path is a devkit defect, worked around and filed (FB-716, FB-717).
