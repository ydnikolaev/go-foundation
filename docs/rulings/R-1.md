## Context
Shared Go code for every project: primitives (clock, retry, ids) and whole modules (auth with its internal packages). An import path is permanent, and a primitive can grow into a module. Units mixed with tooling at the root turn into chaos as they grow (raised by the owner; devkit foundation-kit LR, CTO ruling at devkit commit 677e09ea, relayed by devkit-cto on 2026-11-08).

## Decision
One unit is one capability, one directory under the one fixed prefix `units/` and one Go module (`github.com/ydnikolaev/go-foundation/units/<id>`). `units/` is a constant prefix, not a category: there is never a `prim/` or `mod/` segment; `kind` (primitive | module) is metadata in `units/<id>/unit.json`. The root holds tooling only (config, docs, mk, scripts, UNITS.md, LICENSE, go.work). Inside a module-kind unit Go's own rule applies: subpackages and `internal/`. Each unit has its own go.mod, so a consumer pulls only that unit's dependencies. go.work is for local development across units only. Unit to unit is a plain `require`, declared in config/modules.ini `deps.<id>`.

## Consequences
`make units-check` refuses a go.mod at the root, in a root directory or directly in `units/`, a unit dir without unit.json, an id that is not the dir, and a module path other than `.../units/<id>[/vN]`. The move happened before the repository went public, so `adoption/v0.1.0` was deleted and re-cut as `units/adoption/v0.1.0`: no proxy or sumdb had cached it. Renaming a unit after that is a new unit plus a deprecation.
